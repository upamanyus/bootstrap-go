# Porting the checkers' Rocq development to Lean

The Rocq sources are branch `main` of this repository, checked out read-only
at `~/bootstrap-go` (never edit anything there). This branch (`lean`, checkout
`~/bootstrap-go-lean`) holds the Go checkers unchanged in substance and the
Lean port of their Rocq side.

## Dependencies

- Perennial's Lean port (`.lake/packages/perennial`, branch `lean` of
  mit-pdos/perennial). Framework docs: `.lake/packages/perennial/docs/`
  (`PERENNIAL_PROOF_TUTORIAL.md`, `PERENNIAL_PROOF_REFERENCE.md`,
  `IRIS_PROOF_MODE.md`) and `.lake/packages/perennial/PORTING.md`. Worked
  WP proofs in this setting: `.lake/packages/perennial/Perennial/Proof/**`.
  Rocq → Lean framework names: `.lake/packages/perennial/etc/lean-rename/renames.tsv`.
- The Lean port of the raft election proof (`.lake/packages/etcdGrove`),
  used only by tcheck's raft client. Its `notes/porting-guide.md` is the best
  Rocq → Lean cheat sheet for this framework (names, separation logic,
  tactics): read it before porting anything.

## Layout

| Rocq (`~/bootstrap-go`) | Lean (here) |
|---|---|
| `new/code/github_com/mit_pdos/perennial/{checker,checker/examples,tcheck}.v` | `Generated/Code/github_com/upamanyus/bootstrap_go/…` (generated by `etc/goose.sh`; do not edit) |
| `new/generatedproof/…` same packages | `Generated/GeneratedProof/github_com/upamanyus/bootstrap_go/…` |
| `src/goose_lang/heap_adequacy.v` | `Checkers/GooseLang/HeapAdequacy.lean` |
| `new/checker/<file>.v` | `Checkers/Checker/<UpperCamel>.lean` (`exec_sound_a` → `ExecSoundA`) |
| `new/checker/fn/<goFunc>.v` | `Checkers/Checker/Fn/<goFunc>.lean` (Go name kept as is) |
| `new/proof/github_com/mit_pdos/perennial/checker/examples/*.v` | `Checkers/Checker/Examples/<UpperCamel>.lean` |
| `…/checker/examples/observed/*.v` | `Checkers/Checker/Examples/Observed/*.lean` |
| `new/tcheck/*.v` | `Checkers/TCheck/<UpperCamel>.lean` |
| `new/proof/go_etcd_io/raft/tcheck/*` | `Checkers/TCheck/Raft/…` |

The Go package path changed: it is `github.com/upamanyus/bootstrap-go/…`
here (Lean namespace `github_com.upamanyus.bootstrap_go.checker`, …), not
`github.com/mit-pdos/perennial/…`.

Not ported: `new/proof/symex/` (`wp_symex`, a reflective symbolic executor,
not a checker), the `reflect/` example proofs that use it, and
`new/proof/rocqgoal/` + `gocheck/rocqgoal/` (a Rocq goal exporter).

## Conventions

- Everything in `namespace Perennial`, then `namespace Checker` or
  `namespace TCheck`. Start each file with `/- Port of <rocq path>. … -/`
  keeping the Rocq file's leading comment, plus a `Lean notes:` paragraph for
  anything that differs.
- Keep Rocq identifiers where legal (`teval`, `is_term`, `check_sound`) so
  the Rocq name can be grepped; this is a port of a single development, and
  matching names make the two easy to compare.
- Never weaken a statement to make a proof go through. Never add an `axiom`
  that Rocq does not have. An unfinished proof is `sorry` with
  `-- TODO(port): <what is missing>`.
- No `native_decide`/`bv_decide` (they trust native code). Use `decide`,
  `rfl`, `simp`, `omega`, `bv_omega`, `word`.

## Building

    export PATH=$HOME/.elan/bin:$PATH
    lake build Checkers.Checker.Defs          # a module and its dependencies
    lake env lean Checkers/Checker/Defs.lean  # check one file (writes nothing)

Several agents may work in this checkout at once. `lake build` only the
modules you own (and their already-ported dependencies); never `lake clean`,
never touch `.lake/packages`, never edit another agent's files. Use
`lake env lean` for the edit loop.
